# Ticket description template — short, universal shape

> This is the canonical structure the Sprint Ready Agent reformats every
> Jira ticket description into. **Edit this file to change the shape of
> every generated description.** Add a section, remove one, rename
> another — the agent will follow.
>
> Rules for the agent:
>
> 1. Emit **every heading** below, in this exact order, on every ticket.
> 2. Use `_None._` when a section genuinely has nothing to fill in —
>    never delete the heading. Consistent shape > shorter output.
> 3. Never invent facts. If evidence is thin, put the gap in
>    **Open questions** instead of guessing.
> 4. Keep it short. This template is meant to be scannable in a few
>    seconds, not exhaustive.

---

## Context

_One or two sentences. Why does this ticket exist and who is it for?
Pull from the summary, linked issues, or the reporter's own words._

## Acceptance criteria

_A short numbered list (aim for 2–4 items) of things a reviewer could
independently verify pass/fail. Keep each item to one line._
